# Задание 5 — Проектирование GraphQL API

## Условие

Сервис управления клиентскими данными (`client-info`) используется в различных сценариях продаж и обслуживания страховок. Он предоставляет обширную карточку клиента, содержащую до 500 атрибутов. Потребители сервиса (веб-приложения и `core-app`) в зависимости от сценария запрашивают разные данные, что делает использование классического REST API неудобным и неэффективным.

### Проблемы существующего REST API:
- Каждый ресурс возвращает ограниченный набор данных (документы, родственники и т.д.).
- Для одного сценария может потребоваться 3–5 отдельных REST-запросов.
- Нагрузка (RPS) на сервис увеличивается.
- Передача всех данных в одном ресурсе невозможна из-за большого объема.

### Решение:
Было принято решение перейти с REST на **GraphQL**, чтобы:
- Гибко управлять выбором полей и сущностей,
- Избежать избыточных запросов,
- Оптимизировать загрузку данных.

## Проектирование GraphQL схемы

### Основные сущности

На основании текущего Swagger-контракта были выделены ключевые сущности:
```
type Client {
  id: ID!
  name: String
  age: Int
  documents: [Document]
  relatives: [Relative]
}
```
```
type Document {
  id: ID!
  type: String
  number: String
  issueDate: String
  expiryDate: String
}
```
```
type Relative {
  id: ID!
  relationType: String
  name: String
  age: Int
}
```
Связи между сущностями:
- Client может иметь список Document и Relative,
- Все вложенные данные доступны по мере необходимости (lazy loading через GraphQL).

### Определение Query-операций

GraphQL позволяет в одном запросе получить только те поля, которые действительно нужны клиенту или другому сервису. Это исключает проблему с перегрузкой данных, как в случае одного общего REST-ресурса.

**Примеры возможных запросов**

1. Получение базовой информации о клиенте:
```
query {
  client(id: "1") {
    id
    name
    age
  }
}
```

2. Получение клиента с его документами:
```
query {
  client(id: "1") {
    id
    name
    documents {
      id
      type
      number
      issueDate
      expiryDate
    }
  }
}
```

3. Получение полной информации: клиент + документы + родственники:
```
query {
  client(id: "1") {
    id
    name
    age
    documents {
      id
      type
      number
      issueDate
      expiryDate
    }
    relatives {
      id
      relationType
      name
      age
    }
  }
}
```


## Преимущества предложенного подхода

- **Гибкость**: потребители (core-app, веб-приложения и т.д.) сами выбирают нужные поля.

- **Оптимизация нагрузки**: GraphQL позволяет избежать ненужных запросов и передачу лишней информации.

- **Унифицированный API**: единая точка входа с возможностью выборки связанных данных.

- **Расширяемость**: добавление новых полей или сущностей в GraphQL-схему не требует изменения контрактов или внедрения новых REST-эндпоинтов.
