# Задание 6 — Настройка Rate Limiting в Nginx

Один из партнёров продолжает отправлять чрезмерное количество запросов к API, что приводит к деградации производительности и ухудшению пользовательского опыта других клиентов. Несмотря на внедрение динамического масштабирования, ресурсов системы недостаточно для устойчивой обработки такого количества запросов.

Чтобы избежать подобных ситуаций и обеспечить "честное" распределение нагрузки между всеми потребителями, необходимо реализовать защитный механизм на уровне веб-сервера — **Rate Limiting**. В случае превышения установленного лимита клиент должен получать ответ с кодом `HTTP 429 Too Many Requests`.

---

## Цель

- Ограничить количество входящих запросов от одного клиента до **10 запросов в минуту**.
- При превышении лимита — возвращать **HTTP-статус 429**.
- Реализовать решение с использованием **Nginx**.

---

## Конфигурация Nginx

```nginx
http {
    upstream backend_servers {
        server backend1.example.com;
        server backend2.example.com;
        server backend3.example.com;
    }

    limit_req_zone $binary_remote_addr zone=mylimit:10m rate=10r/m;

    server {
        listen 80;

        location / {
            limit_req zone=mylimit;
            limit_req_status 429;
            proxy_pass http://backend_servers;
        }
    }
}
```

| Директива          | Назначение                                                       |
| ------------------ | ---------------------------------------------------------------- |
| `limit_req_zone`   | Создаёт зону, в которой хранятся лимиты по ключу (IP клиента).   |
| `rate=10r/m`       | Указывает допустимую частоту — 10 запросов в минуту.             |
| `limit_req`        | Активирует применение лимитов внутри `location`.                 |
| `limit_req_status` | Определяет статус-код, возвращаемый при превышении лимита (429). |
| `proxy_pass`       | Проксирует запросы к backend-серверам.                           |

### После применения этой конфигурации:

- Каждый клиент (идентифицируемый по IP) сможет отправлять не более 10 запросов в минуту.
- При превышении лимита клиент получит ответ с HTTP 429 Too Many Requests.
- Производительность приложения стабилизируется, и ресурсы будут равномерно распределяться между партнёрами.

### Рекомендации

1. При необходимости различать партнёров по токену или другому идентификатору, вместо `$binary_remote_addr` можно использовать произвольный ключ, например, `$http_api_key`.

2. Для более гибкой настройки можно добавить **burst** (всплеск) и **nodelay**, если допускается кратковременное превышение лимита.

```
limit_req zone=mylimit burst=5 nodelay;
```
